No code/tests/native work. No implementation acceptance. Existing report-only coordination under root's resume-directory claim continues; authenticated bus unavailable as previously recorded.

## Core decision

A dispatched input is not proof that the parser understood it, and a response without a known refusal is not proof the action succeeded. Preserve existing opcode/calibration behavior for its existing verbs; do not widen its semantic authority. Add an explicitly separate `observed-exact-attempt` evidence tier for newly admitted noncanonical verbs. It records what the user actually tried with a uniquely verified object and the bounded response class. It is durable module knowledge, but does not set success=true, allowedVerbs, attribute flags, canonical semantic aliases or submit-ready status by itself. In menus it remains a remembered exact suggestion with provenance, subject to the existing complete-form run policy and current applicability guards. A click on that suggestion is another attempt, not self-confirmation.

There is no defensible general semantic-success classifier in the examined source. This proposal therefore does not promote two non-refusals into semantic success for broadened verbs. If the desired product requires broad new verbs to become confirmed submit-ready commands, that promotion remains blocked pending an actual structural/effect witness or an explicitly approved weaker product tier. Persist attempts immediately rather than lose knowledge while waiting for a success proof. Existing confirmed opcode/exact/manual records retain their current interpretation; do not relabel old evidence as stronger.

## Admission identity and lexical shape

At prepare capture pageEpoch + submissionId, static executable digest (when authoritative), UndoRestoreSync.generation, final normalized command, producer, objectId, exact form, current verified noun/candidate IDs and manual candidate revision if any. If executable authority unavailable, do not enqueue durable new module facts under weak release/serial identity; retain only session attempts pending the separate identity design. At captureAfter and record require unchanged digest/page/generation; revalidate same object ownership/reference. Discard stale asynchronous callbacks, never hydrate current module and append an old event into it. Deduplicate durable writes by executable digest + pageEpoch + submissionId + evidence lane; a manual and ordinary path cannot both claim the event.

For new generic unary observations permit one dictionary-owned leading verb token and an exact current verified noun phrase only. Existing established multiword aliases retain existing recognition; no arbitrary two-word split, no compound commands, addressed commands, topic clauses, questions, quoted speech, preposition/instrument suffixes or abbreviated pronoun references. Dictionary membership proves vocabulary only. Ambiguous candidate IDs, custom parser references failing existing referenceVerified gate, absent scope or malformed final text fail closed. Do not infer unknown verb semantics from incidental set_attr opcodes; its successOps stays empty and it cannot enter VERB_FLAG/allowedVerbs merely because an attribute changed.

## Response boundary and outcome contract

The actual recorder is TurnRecorder; no distinct TurnClosure implementation was found in bounded js search. TurnRecorder._boundaryStamp:173-180 freezes endLine and captureAfter immediately before the later command executes; _settle:185-200 freezes after 450ms if unstamped and runs analyzers. AttrCalibrator verbSuccess captureAfter:415-436 captures lines[startLine,endLine) and parent links. analyze:450-475 uses that frozen text. These are response ownership bounds, not parser-completion or main-prompt proofs. A later command may be an answer to a disambiguation/yes-no prompt. A visible LineInput also cannot distinguish main prompt from clarification.

R2 therefore records closureKind (`later-dispatch` or `timer-window`), response snapshot/fingerprint and boundary IDs as attempt metadata, never `parserCompleted=true` from these bounds alone. Do not extend capture into later output and do not read live DOM during delayed analyze. Timeout is inconclusive, not success. Exclude echoes, hidden-probe-owned lines and app chrome from new response classification (current capture maps all BufferLines text; it is not already filtered proof). Partial/mutated lines and output arriving after capture are limitations, not a complete response assertion.

Outcome classes for new tier:

1. `dispatched-only`: no attributable response/consumption witness; durable attempt text may be retained, no positive count.
2. `response-observed`: bounded game output exists; proves only that output was observed after this dispatch, no semantic acceptance count.
3. `recognized-refusal`: existing refusal/precondition/ambiguity patterns match; retain negative classification and no promotion. This conservative pattern match is not a complete failure detector.
4. `prompt-or-continuation-suspected`: known disambiguation/incomplete/yes-no/more wording, char-input continuation or observed prompt ownership; no promotion. The current recorder exposes no reliable general prompt-kind signal in these files. Unknown prompt kind remains unknown, not main prompt.
5. `effect-witness`: only already specified verb-specific opcode/state relation under its original calibration contract; handled by existing lane. A generic unknown verb never receives this merely from incidental mutation.

Examples: `Which key do you mean?`, `What do you want to light?`, `Do you really want to ...?`, `[Press any key]`, `First you must ...`, `You need to ...`, `Nothing happens`, `Okay`, and unrelated incidental object narrative all give zero new semantic-success confirmations. Legitimate narrative containing '?' or 'not' may conservatively remain unknown; absence of either does not make it successful. A recognized refusal may still accompany an unrelated opcode mutation: preserve ambiguous exclusion in existing path (AttrCalibrator:462-483).

Manual revision precedence remains unchanged, including revision/object/module/generation checks in LearnedWords.recordWitness:114-127 and exactly two distinct recorder submission witnesses. Do not broaden what counts as a successful manual witness in this patch: new attempt-only outcomes must not be passed as behavioralAccept=true. An explicit user revision can be saved as authored knowledge immediately while observed semantic confirmation remains separate.

## Review boundary and future verification

This contract intentionally narrows the new durable layer to facts the app can actually know. Reusing the legacy `behavioralAccept` classifier to promote arbitrary dictionary verbs is rejected. A stronger tier requires a separately reviewed producer of parser completion + supported grammar/effect evidence; the current 450ms timer and next dispatch cannot supply it.

Focused future checks: final edited line rather than proposed voice/radial text; blocked injection records no attempt; typed/synthetic de-duplication; mixed inject callers rejected until tagged; exact provisional selection yields only later observed evidence; manual precedence and revision changed during timer; module/generation switch; timer truncation and rapid second command; disambiguation reply and char continuation; generic Okay/no-refusal zero promotion; ordinary opcode calibration unchanged. No tests were run, and the callsite table is a bounded design inventory rather than every submission caller certified.
