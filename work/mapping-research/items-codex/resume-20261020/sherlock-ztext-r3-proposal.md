# R3 proposal: dictionary lexical ownership must not promote partial escapes

R2 final verdict is REVISE. The full309x2 comparison and both paired reruns isolate a deterministic Acorn Court regression: incomplete escape at entry10687 yields a printable prefix `tennis`, which becomes object vocabulary and a preferred head, merging ball candidates with court/net and losing the ball group underline. Old `tennisb` was also wrong; restoring that corruption is not a repair. The decoded object short names are unchanged. Native/raw evidence in sherlock-ztext-r2-shared and independent reviewer findings establish this consumer failure.

Dogslife room47 is a separate intended correction: actual raw packed text encodes ASCII38 and native NORTH/NORTH/LOOK prints `Junction Freeblewhizz & Whizbang`; candidate agrees, baseline loses ampersand. Do not conflate that with Acorn or label Acorn flaky.

Propose retaining the accepted prose decoder semantics and exact compiler sentinel owner repair. Add a bounded dictionary-text entry API in ZRamReader that uses the same raw decoder with optional completeness metadata. Incomplete or unsupported ten-bit escape must not create a string claiming standalone dictionary-word ownership. Keep raw dictionary entry/address/data records available, but omit that unqualified text from words/reverse aliases and return an empty text at grammar dictionary construction; no invented suffix, punctuation stripping, title branch, old bug shim or underline exception. The general prose decoder continues to ignore unfinished constructions as specified; dictionary lexical authority is stronger than displayable prefix text.

Metadata can be optional on `_decodeZscRaw`, preserving all existing string callers and D143 raw recursion; no persistent cache owner or VM write. The dictionary API reports a word only when the bounded stream has no unfinished/unsupported escape. Both ZRamReader `_parseDictionaryUncached` and GrammarProvider `_d198RawDictionary` must use the same owner. Do not silently bypass remaining grammar linkage checks when a required alias lacks valid text. Existing complete words, ordinary nine-zchar truncation, supported completed escapes, abbreviations spacing for prose, and dictionary native encoded-key comparisons retain their current contracts.

Required tests before freeze: original Acorn entry decodes a prose prefix but cannot own standalone tennis; real ball alias remains valid, actual native ball group underline/ref candidates and inventory identities survive on fresh state; encodeDictWord('tennis') differs from the original key. Keep R1 table/sentinel regressions,28controls, original Sherlock3entries, Dogslife ampersand native heading. Add complete versus incomplete boundary and unsupported dictionary controls, ordinary truncated long word preservation, both dictionary owners same decision. Reconcile all changed family classifications and dictionary availability rather than waive regressions. Non-author adversarial design before edits, focused/native/ operator0FAIL before fresh immutable R3 full309x2 and final current-source review. R1/R2 evidence remains preserved; no overall/classifier/title closure.

Open design question for review: should the initial dictionary boundary reject only unfinished escapes, or also completed unsupported escape codes whose omitted character would similarly create an unqualified prefix? Favor both, since neither licenses exact lexical ownership; extended mapping itself remains out of scope. Review against D64/D107/D143/D144/D147 and D198/ARCH64, existing dictionaryWordKey/encodeDictWord and actual downstream aliases. No implementation under this proposal yet.
