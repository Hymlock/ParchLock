# Pocket R3 design draft for integration-owner consensus

Status: proposed, not implementation authorization or named-engine consensus. Supersedes the one-key R2 direction only after actual reviews. Root+independent source investigations and two bounded native captures are linked in power-recovery-pocket-compare-direction.md. No new blind claim.

## Result required

Keep Sherlock's pound note available to parser/action scope while the coat is unworn, omit its inventory label in that context, restore its label when coat is worn, and draw it normally once directly held. Keep real parent150->287->302->232 unchanged until an ordinary native TAKE changes it. Pocket287's own hidden label and childless hidden rope remain omitted. More/manual suggestions remain available under their existing contracts.

## Proposed implementation boundary

Use the existing inventory-label projection contract, not removal from Actionable.payloadPool or rewrites of physical parentId. Keep the current qualified hidden-label recursion so descendants can enter the scope-bearing inventory rows. Add a bounded executable-owned inventory label rule in the reader layer that produces those rows, shared by snapshot and the provider re-root (walkVisibleDescendants is called from both). A provider-only patch would leave snapshot consumers inconsistent.

The rule's data must explicitly identify pocket287, coat302 and worn34 on the validated exact Sherlock executable. Validate representation/family, actual player/root, true object bounds and current raw parent chain before applying it. It is a label rule, not a general wearable/container capability. Propagate strict labelSuppressed:true to pocket descendants when the native pocket section would be omitted; do not clear an existing suppression, add missing inaccessible children, change attributes, or synthesize command forms. Direct-held note is outside that subtree and unaffected. Existing container/opaque/invisible/NDESC rules stay in force before the projection. No names/prose/room-number inference.

Final schema and invalid-rule behavior must be explicit in the integration owner's proposal before code. Reuse existing executable fact validation rather than invent a new universal dynamic-rule language. Do not make inventoryHiddenScopeRetained:true a blanket substitute: that would also expose unrelated hidden holders, requiring separate proof.

## Affected consumers and prior guards

ZRamReader.snapshot and ZRamProvider refresh both use the shared walker. Actionable.RenderInventory uses EquipmentUI.labelRows (or strict suppression fallback); EquipmentUI model/presentation must omit the suppressed note. Actionable payloadPool/reference resolution must retain it for scoped actions. WorldModel treats suppressed rows specially for holder recovery, so actual player/root resolution must remain unchanged. EquipmentUI's separate labelParentId must not become command custody. Existing D1/D16 label-versus-scope, D31 nested custody, D53/D75 root recovery and D260 direct-held command restrictions are prior-fix guards.
