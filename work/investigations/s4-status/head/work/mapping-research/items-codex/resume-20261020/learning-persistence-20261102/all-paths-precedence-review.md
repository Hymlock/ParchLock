# All-paths adaptation and learned-item precedence review

2026-11-02; bounded read-only source/artifact review. No browser/native/timer/census runs or runtime edits. Direct operator steering governs: confirmed learning overrides usage ranking for the learned item/action only; unrelated actions retain usage ranking. This is a proposal direction requiring plan/design review, not implementation consensus.

## New renderer evidence

Read browser-learn-ui.json and browser-reopen-ui.json renderedRadial records. Both explicitly use actual Actionable.Open public renderer, not physical gesture. Held-lamp main menu remains Examine/Drop/Give/Put/Unlock/More/Tools. More before teaching: Take, Abra, Abracadab, Adjust, Ahriman. More after two LIGHT/DOUSE pairs: Douse, Light, Take, Abra, Abracadab. After isolated browser close/reopen More returns to the initial order. This directly reproduces a visible change then loss in the public renderer's More submenu. It is not evidence that LIGHT/DOUSE became confirmed learned commands or phone gestures were reproduced. Their durable exact forms remain absent in prior captures.

Source explains it: Actionable.Init subscribes to accepted submissions and calls noteUsage regardless of semantic result (1110); usageCounts/verbCounts and radialInteractionCounts/overlap/intent counts are in-memory. usageCount adds command usage or stem verb use plus interaction minus overlap (1089). Qol.RankRadialCommands (730) sorts uncapped UsageCount FIRST, Prior SECOND, original index last. A large confidence score cannot override any higher usage count. More builds vocabulary suggestions Enter:false (2710), whose ranking therefore adapts after typed submissions without proving success. Both failure and success submissions can affect usage. This is use frequency, not learned acceptance.

## Bounded precedence design direction

1. Admit eligible actual one-object exact-form observations under the reviewed unique/verified/dictionary/frozen-response policy, distinct from usage and manual-revision witnesses. Store confirmed evidence per static executable and stable object ID; no LIGHT/DOUSE special case and no attempt-to-semantic promotion.
2. Define a shared projection of confirmed exact item forms after loading and current applicability checks. It returns descriptors carrying evidence identity, objectId, static module identity, exact form, context/generation for the rendered command, and any stronger authoritative scope. Durable knowledge survives; generation in command descriptor refreshes. Do not persist the descriptor's current state as a learned fact.
3. Resolve source/authority filtering BEFORE ranking. Respect authored owner rules, light/inspect policies, worn/nested restrictions, ambiguous references, ignores, revised manual forms and scope freshness. A learned form cannot resurrect a prohibited command. Dedupe identical spelling/object; preserve stronger scope on duplicates. Canonical aliases and distinct exact accepted spellings require explicit dedupe policy, never guessed synonym mapping.
4. Carry a dedicated confirmed-item evidence marker into the final radial slice DTO. It must be computed from trusted provider evidence, not Label/Enter/Score/Usage or caller-supplied objectless text. Qol.OpenRadial currently reranks centrally, so fixing order only upstream will be undone. Define comparator as confirmed-item tier FIRST, existing UsageCount/Prior/original-order inside each tier. Only current object-specific complete command descriptors qualify; Tools, stems, dictionary-only suggestions, one-attempt projections, or globally frequent verbs do not.
5. Apply this to ordinary object and Yourself via the same provider/projection, preserving source annotations through SemanticActions and slice mapping. Main learned forms should appear as actual item commands; do not merely pin vocabulary choices in More. In More, if a learned spelling is also listed, dedupe or mark/rank it from the same trusted evidence. Keep unrelated suggestions/actions' usage ordering unchanged. Explicit custom slices/manual revisions retain their distinct user-intent policy; classify precedence explicitly instead of silently overriding them.
6. Tap-time validate the descriptor again; old radial cannot submit learned command for changed module, object, noun, context or authoritative state. For a learned spelling the durable record alone is not the entire live applicability witness.

Operator's phrase can be satisfied by learned tier rather than replacing radial usage. Do not globally disable adaptation, persist usage counts, infer arbitrary exact learning from usage2, give every learned verb priority for every object, or treat More position as confirmation. Current source comment claiming usage authoritative must be amended by the new explicit operator rule in PLAN/ARCH before implementation.

## Focused durability and precedence proofs required

- Ordinary native successful pair twice: no confirmation after first; persisted exact form after qualifying evidence; rejected/ambiguous/prompt-only and duplicate submission never qualify. Confirm captured real response boundary/provenance, not counter values alone.
- Native held lamp public renderer: confirmed LIGHT/DOUSE appear through normal item provider with durable learned tier; More lexical versions cannot outrank/bypass or duplicate them. Preserve current authoritative state-side behavior if owned by a light policy. Main/More/Yourself and any intended autocomplete seed parity.
- Same persistent isolated profile: settled unsaved application exit, fresh page, reacquisition WITHOUT reteaching retains identical prior evidence identity and learned tier, while session usage has reset. Earlier-save restore/restart preserves knowledge but recomputes lamp state/scope. Do not satisfy assertion by taking a newly learned action before verifying old evidence.
- Two different object IDs sharing noun/verb: only proven owner gets learned tier. Other object and unrelated verbs retain pre-existing usage comparator; a globally frequent failed command/stem cannot displace confirmed item command. Ambiguous shared radials fail closed unless every member independently qualifies under allowed shared policy.
- Learned tier0 versus unlearned usage100; two confirmed commands keep deterministic tie behavior; existing usage tie/prior/order and _usageLeader visuals remain correct. Define leader visual meaning under tier precedence so an unlearned high-count row is not misleadingly crowned as preferred over learned tier.
- Worn/nested/ground/consumed/out-of-scope, ignored/revised manual, state-owner light scope, stale open radial, module switch/digest not ready; each must preserve authority and no new automatic submission from mere suggestion/projection.
- Static header-collision pair isolation, same executable alternate wrapper, queued write/quota/erase epoch and old-data retention policies as prior review. Pending-write exit remains separate design risk unless agreed scope includes barrier; settled proof alone cannot certify it.

New installed Actionable/Qol/SemanticActions equality reported by parent supports shipped-source match for this ranking path; physical phone loaded cache and gesture/menu state remain uncaptured. No APK/implementation acceptance or whole-system completion is established here.
