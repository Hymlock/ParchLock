## Learned evidence versus radial usage: current precedence and gap

The current shared radial sort has no learned-item-first lane: Qol.js:730-762 sorts solely usage, prior, original index. Merely increasing learned confidence/prior cannot override a frequently used unrelated entry. Object radial producer keeps confidence separate from usage (Actionable.js:2812-2817), and Yourself entries also acquire usage (EquipmentUI.js:149-155). This is a concrete missing path for the user's amendment: learned membership must be represented on the actual rendered entries reaching the common ranker, and affect ranking only when evidence admits that item. Unlearned entries must retain D110's existing tuple. Suggestions, labels, dictionary hits and command-use counts cannot be used as aliases for confirmed learning.

There is also source-selection precedence before radial ranking. SemanticActions.resolveForObject applies structural forms, then confirmed object, confirmed build, compiler grammar/profile, migration compatibility (js/SemanticActions.js:406-411). Its earlier step wins a duplicate verb (line 399), though duplicate rendered commands merge evidence. Actionable.referenceFor prefers current CommandNouns over VerifiedNouns (110-150). Neither mechanism is a universal learned-item override. The amendment should specify command admission/form authority separately from display ordering; it must not bypass current scope/state guards (Actionable.radialCommandCurrent:2763-2776) or authoritative owner spelling policies (ActionSynth.js:630-635).
