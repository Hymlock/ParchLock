## Accepted contract

- Separate digest learning accessor; unchanged general ZRamReader.gameIdentityKey. Five new digest keys with old generators still recognized for ownership/erase. No digest means no durable access, no null/unknown bucket and no sticky null hydration.
- Existing digest value has precedence even if malformed; the owner's validator handles it without falling back to legacy. Preserve strong module identity/path/VM consistency and stale-callback checks.
- Legacy only when exact kind/key/generator and complete singleton current-digest owner attribution pass, including durable digests union; reject overflow, path-only, unknown/multiple owners, bad index and erase history. Multiple paths belonging to the same exact digest are valid. Unindexed/ambiguous data stays byte-identical, unserved and honestly retained/unassigned.
- Owner schema validation occurs before conditional copy. LearnedWords rewrites only its validated embedded identity; rows/manual/ignored/witness state retained. No row splitting or blind merge with existing new value.
- Lock-protected import rechecks eligibility and new-key absence, and preserves both legacy bytes and index. No Web Locks means no legacy import/serving; normal new-key writes retain existing behavior. New/legacy erase, pending erase and nonzero epoch disqualify import to prevent resurrection.
- Pending hydration remains neutral and retryable for all five owners; not just diagonals. Commit success makes later retry eligible to read new key. Failure/quota/erasure/stale identity remains neutral with honest status, never marked imported/durable.
- Both diagonal consumer entries and writer hydrate/ensure; module switch resets before access. Digest-stable restore/restart keeps module calibration. No callback installs A into active B.

## Finite implementation clarifications

1. **Conditional copy binds the payload as well as ownership.** Under lock compare the authoritative legacy raw value with the exact raw value the owner validated, or re-read and validate inside the conditional operation. Existing read() may return a queued snapshot (LearningStores:233), so a stale pre-lock validated projection must not overwrite a newer legacy value while the owner remains the same. Defer import while relevant older legacy writes are pending, or include their ordering/version in the same serialized conditional operation. No demand for a permanent value hash is implied; raw-string equality + lock/queue ordering is sufficient.
2. **Pending state is distinct from hydrated-empty.** Existing owners mark their hydrated identity before synchronous read. The implementation must undo/avoid that marker for import-pending, expose explicit completion/invalidated status, and retry. Deduplicate the pending import per target key so repeated direction enumeration does not queue one per call. A failed import must not leave a forever-pending marker. Use only successful durable write acknowledgement to expose imported value; quota-dropped/written-unindexed/erased are not `imported`.
3. **Fresh observations win the race.** If neutral pending hydration receives a genuine current observation, do not overwrite that live learning with the later imported snapshot. Choose one explicit policy: defer recording until hydration finishes while preserving the immutable observation, then apply it once; or let its new-key write win and cancel the copy. Do not silently lose either successful current observation or make a blind legacy/new merge. This applies to each owner, not only diagonal state. On identity change discard the pending active installation, while an already authorized copy may safely finish only for its captured key/owner.
4. **Erase-safe identity stays captured.** The queued copy must carry target identity/owner/reset binding captured at eligibility, not call currentOwner at delayed execution and attribute A's value to B. Bound resets only clear matching active identity; all copied/read identities must use the same new key shape. Existing commit checks hydration revision/epochs (LearningStores:247-255) must be applied to both keys and copy eligibility, not bypassed through an ordinary fallback persist.
5. **Preservation status is reviewable.** Surface retained/unassigned and pending/failed import distinctly in available learned-data diagnostics; no destructive reset/delete of legacy. This can be concise diagnostic text/state, not a new migration UI. Safe singleton import is explicitly operator-authorized narrow retention work; document that exception without generalizing to unrelated migrations.

These are bounded concurrency/lifecycle conditions directly implied by the proposed conditional import, not blockers on unknown historic corruption. With them adopted, root may implement. Focused checks should exercise raw-source change while queued, target write before import, pending-to-ready retry, quota/erase terminal outcomes, per-owner live observation during import, singleton/multiowner/unindexed retention, A→B callback isolation, and both first diagonal consumers. Actual implementation still requires independent current-checkout review.
