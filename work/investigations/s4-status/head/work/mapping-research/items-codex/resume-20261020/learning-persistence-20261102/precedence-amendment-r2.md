## Required implementation contract for slice A

1. Observation admission and outcome classification remain a prerequisite. An accepted input or usage increment is not proof of action success. R1 review's provenance, response-boundary, ambiguity, manual-revision and submission-id exclusions must be resolved before generic observation code.
2. Project confirmed exact forms through one shared item-command provider for ordinary and Yourself radials. Apply module identity, verified unique reference, ignores/revisions and authored live applicability restrictions first. A learned record cannot resurrect a filtered command or persist old lamp state.
3. Carry trusted item/action confirmation metadata through descriptor and final slice mapping into Qol's final comparator. Compute the marker from current provider evidence, never arbitrary labels, scores, frequency, dictionary membership or caller-supplied booleans alone. Sorting upstream alone is insufficient because Qol reranks.
4. Comparator: confirmed applicable item/action tier first; existing usage, prior and stable order within tiers. Unlearned entries keep existing relative ranking. High usage for a failed or unrelated command cannot outrank a confirmed item action. No global usage persistence or disabling usage ranking as a substitute.
5. Dedupe equal item/form entries retaining stronger authoritative scope and learned provenance. Preserve More and user-created/manual slice policy. Review how usage-leader decoration reflects the new tier. Tap-time checks reject stale module/object/reference/state descriptors.
6. Verify learned0 versus unlearned100, another object sharing the verb/noun, ignored/revised forms, worn/nested/current light policy, stale menus, actual fresh reopen before reteaching, earlier-save restore and ordinary/Yourself/More parity. Use the real successful lamp route once implementation is approved; do not repeat unchanged native proofs merely to restate findings.
