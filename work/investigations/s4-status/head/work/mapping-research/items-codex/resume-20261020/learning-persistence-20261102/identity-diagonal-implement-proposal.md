## Shared identity and owned import helper

Expose LearningStores.learningIdentity(mem, {requireZMemory}) (or equivalently a small shared ZRamReader accessor with no localStorage code) returning `{identityKey:'sha256:'+digest,digest,legacyIdentityKey}` or null. Require a valid 64-lowercase-hex digest from ModuleLibrary.currentExecutableIdentity selected for current StoryPath; require Z format and stable immutable header agreement with supplied memory for Z-only stores. Stats can use current Glulx identity without Z memory. Missing/current-path mismatch identity fails closed: no shared unknown/null writes or legacy reads. Do not cache a null identity as hydrated. Current VM starts after executable identity capture resolves (ModuleLibrary:386-438,508,518), so normal production readiness precedes first observation. Harnesses must explicitly supply ModuleLibrary identity rather than rely on release/serial fixtures.

Add one LearningStores helper `readForIdentity(kind, inputs, legacyInputs)` returning `{value, source, legacyKey?}`. It must:

1. Generate/read the new key through LearningStores.read first, preserving erase hydration revision/epoch behavior. A present new value, including malformed value, is authoritative as the candidate for the store's own validator; never silently fall back to legacy because current data failed validation.
2. If absent, require a valid ownership index and no new-key tombstone, eraseEpoch or pending erase. A prior explicit erase of the digest key prevents reimport forever; otherwise legacy bytes would resurrect erased learning.
3. Generate exact legacy key for that same kind. Require index entry kind/key match, entryValid, nonempty complete owners, no ownersOverflow, no pathOnlyDropped, no tombstone/pending erase and no nonzero eraseEpoch. Require every owner.digest to be a valid digest equal to current digest; require the union of durable e.digests (if present) and owner digests to be EXACTLY [current digest]. Missing/null owner digest disqualifies. For old entries without e.digests, only the complete nonoverflow owner list can establish that singleton. Repeated paths for the same digest are acceptable; sole path without digest is not. Each owner.inputs must derive the exact legacy key. Stats legacy `unknown` is eligible ONLY under the same strict single-digest attribution; absence of owner evidence is not ownership.
4. Read legacy through LearningStores.read and return it for that store's existing schema validation. Do not mutate/delete legacy key/index or infer ownership from installed library uniqueness/name/path/release. Preserve ambiguous legacy bytes unchanged and report source='ambiguous' or 'unattributed' to callers/audit diagnostics, without serving those values.
5. Store validates payload/version using existing rules. For LearnedWords only, validate old embedded gameIdentityKey against the exact legacy identity, then copy into new object with embedded gameIdentityKey set to digest identity; preserve all rows/ignored/manual/witness data. Other store JSON schemas need no identity-field rewrite.
6. On successful safe import, persist the validated projection under the new digest key via normal LearningStores.persist, including matching bound reset callback. No deletion. New-key write must recheck the same source ownership/erase epochs and absence of a newer current value under existing PL_learning_store lock; otherwise a concurrent writer/erase could invalidate the earlier read. Implement import as an explicit queued conditional-copy snapshot, not an unguarded fallback persist. If Web Locks are unavailable, serve no legacy import rather than pretending the two-key operation is atomic; new digest learning continues via existing no-lock persistence. Return imported value to consumer only after protected validation is authoritative, or provide synchronous read eligibility with a pending import and do not call the copy durable until its promise succeeds.

The index is attribution evidence under this explicitly requested policy, not a cryptographic binding of bytes. Old unindexed writes, a historical crash between value/index writes, or externally modified storage cannot be reconstructed. Document this limit; do not claim impossible forensic ownership certainty. Strict singleton policy is the requested safe-compatibility boundary, not evidence that all historic records can be recovered. If independent review requires crash-proof import, existing format cannot meet it; retain such legacy data unserved and flag that bounded limitation instead of guessing.

Minimal synchronous consumer option: helper reads verified singleton legacy value, consumers validate/use it, and conditional import is queued. It must still honor new-key/legacy erase epochs and must not return a record while LearningStores reports pending erase. Review must explicitly accept current singleton index attribution as sufficient for serving before copy; otherwise hydration needs a pending return + retry on completion. Prefer the latter for rigorous lifecycle safety, without blocking/async-await inside direction enumeration.
