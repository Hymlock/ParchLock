# Adversarial design review — 2026-11-04

Verdict: ACCEPT the proposed narrow keyboard design before implementation, subject to the explicit validation details below. This is design acceptance, not source/implementation acceptance.

The native document capture listener addresses the proven descendant GlkOte stop-propagation cause. Named once-only registration, removal of the old bubbling ArrowUp/Down movement branches, eligibility checks before clearing, and cancellation before Inject together prevent duplicate dispatch and draft loss. Leaving lib/main.js untouched limits regression surface. Keeping ordinary arrows and legacy aliases is appropriate. Ctrl+Shift direction is n/s, not parser up/down.

The proposed single-total-LineInput and visible/enabled requirement is conservative and consistent with the fail-closed single-prompt precedent in Input.SubmitPrompt. No visible CharInput must mean all char prompt windows, including GridWindow requests; do not scope that exclusion to BufferWindow. The target exclusion must inspect ancestors (closest), including descendants of buttons/links/contenteditable, rather than only target.tagName. An event with repeat=true may be consumed only after the same eligibility checks; blocked controls retain ownership. Mobile readonly line input is intentional, so disabled is a guard but readonly must not automatically veto an otherwise valid mobile prompt. Ordinary Ctrl+Up/Down behavior should be compared with baseline, not asserted to reach the existing body handler (GlkOte may own it first).

The overlay list matches or strengthens existing DirectionalRadial.CanOpen / CharKeys.autoPadBlocked precedent: native/app dialog state, radial, mobile full-screen map, equipment, and the shared direction pad. Desktop map-open must remain eligible. Require no storyless/recovery state if an anomalous stale input could survive there; a no-story class check is a harmless direct guard. All guards should fail closed if prompt eligibility cannot be determined. No broader shared overlay or submit-path refactor is needed for this fix.

Existing Input.Clear + Input.Inject(..., true, user-navigation) uses the established D86 non-typed choke point. Its success/failure is the accepted submission result. Verify the new source tag still joins normal history/recorder behavior and is not mistaken for an automatic probe. Actual native-key positive cases, draft preservation negatives, repeat, rebind, aliases, modifier controls, and three-engine/operator gates described in the proposal are appropriate. Documentation/tooltips must clearly include both Ctrl and Shift; changing KeyboardNavigation alone leaves js/Map.js:202's Shift+ prefix inaccurate.
