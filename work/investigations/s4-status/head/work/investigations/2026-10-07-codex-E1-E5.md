## E1 Yourself dwell

EquipmentUI.yourselfCommands rejects references unless both unique and verified, then filters command forms against dictionary and object/context evidence. Drag dwell at 750ms still invokes openYourselfRadial. Recent Treasures custom-parser objects deliberately remain unverified, so they get no dwell commands even when ordinary Use exists. That explains a narrow class, not an all-module regression. Check pointer/dwell and readyForYourself gates in a real ordinary Inform game before weakening uniqueness or verified submission. Preserve exact object IDs, dictionary/arity checks, modal/probe ownership, and short-drop behavior. A safe editable suggestion may have different eligibility from automatic submission.

## E2 first-load import

Qol.ImportPackageData rejects any nonempty Save when ParchLock.GameId is empty. ParchLock.Init reads only persisted PL_GameId_<filename>. Engine native save dialog assigns GameId later (lib/main.js Dialog). This is a lifecycle availability defect, distinct from ModuleLibrary executable digest/summary. Resolve the engine's actual save namespace as soon as available and propagate it in the same session; never equate SHA256 to the engine's save ID or trust the imported package to establish identity. Preserve mismatched-story rejection and transactional rollback. First fresh load, not a warm persisted fixture, is required for the positive check.

## E3 warning

StatTracker.requestStatusFulfillment keys disclosure by _storyEpoch, so every story load can show it again. NeedsNotice also considers numeric probes rather than treating the Equipment entry warning as installation-owned behavior. Replace with installation-generation acknowledgement, retained across launch/restore and cleared on uninstall/reinstall; define built-in hide/restore semantics. Module reinstall must not inherit old acknowledgement. Heading WARNING and the requested humorous bag/battle explanation are product text. D204 probe span/modal ownership must remain: no command behind warning and no repeated warning on Refresh/reopen.

## E4 transcript

Qol.GetTranscriptText clones only current BufferWindow DOM. No durable playthrough transcript owner is used by that reader; DOM pruning/replacement therefore loses history. Implement append-only output capture tied to executable/playthrough identity, not screen text snapshots that duplicate or lose lines. Keep hidden stat/carry probes and command echo policy aligned with existing transcript exclusion. Persist/join transcript with save packages, preserve old package compatibility, isolate separate modules/playthroughs, and define restore/new-game lifecycle. Import must not overwrite an unrelated playthrough archive. Quota failure must not prevent gameplay or save import.

## E5 differentiated objects, stats and mutations

EquipmentUI instance badges compare exact lowercased model names, while Actionable's displayed phrase and command reference are separate. The badge is not the root of inability to address an object: upstream name/reference correlation and custom parse_name verification need tracing for both sword IDs. Fix distinct observed descriptors without granting commands from shared dictionary synonyms; D150/D201 uniqueness guards and Wumpus true duplicates must survive.

StatTracker.applyProwessReply already parses a substring for damage/hit odds, but the measured PROWESS_REPLY eligibility is a full sentence template requiring 'wield only your' and 'armor is only your' plus uninjured/full HP. Equipment changes can invalidate that template. Inspect actual changed-weapon reply before changing pattern; strict reply eligibility should permit authored optional equipment wording without adopting arbitrary narrative numbers. No confirmed claim that sword pickup alone causes damage loss.

RAM object identity can remain unchanged while name/property text changes. E5c needs current structural/name refresh and uniquely object-owned mutation text correlation after every accepted turn; do not rely only on TAKE/DROP or manual INVENTORY. Preserve current probe privacy, parser verification and nested hierarchy. Determine whether payload refresh or cached observed display name is stale before editing. No hidden turn-consuming refresh command should be added as a universal solution.
