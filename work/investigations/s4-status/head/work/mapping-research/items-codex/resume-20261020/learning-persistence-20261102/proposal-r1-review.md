# Proposal R1 adversarial review

2026-11-02. Independent non-author review of fix-proposal-r1.md against bounded current-source reads; no browser/device/timer/census runs or code changes. This is a subagent review, not a vote attributed to another named repository seat.

**Verdict: REVISE before any runtime implementation.** The three defect/risk categories and stated evidence qualifications are sound. R1 is a scope document, not yet an implementable consensus design. In particular B deliberately leaves identity preservation unresolved and C leaves the exit contract unresolved.

## R1-1: broad admission must not make arbitrary accepted prose a semantic proof

SliceA1 retains the existing response policy, but widening changes its risk domain. verbSuccess.analyze treats any nonempty response without refusal patterns as behavioralAccept; for extra forms it adds generic question/not/precondition guards. This can falsely confirm non-action acknowledgments, accepted commands that did something else, multi-turn prompts, incidental object text, or game-specific failures absent from those patterns. Conversely legitimate successful narrative containing a question or negation can be rejected. Dictionary + unique object proves lexical/reference eligibility, not a unary action's grammar or successful effect.

Revise with an explicit exact-form-only contract: retained behavioral threshold proves observed parser acceptance under the existing policy, never opcode state/capability or unconditional applicability. Spell out whether broad unrecognized one-word verbs are deliberately allowed at that evidence tier, and describe how partial/disambiguation/prompt-only turns are excluded using real recorder/VM prompt boundaries. Do not imply arbitrary multiword support: current generic split has one leading word plus noun, with only established multiword aliases. Preserve existing opcode calibrations byte-for-byte; unknown verbs must not gain state inference from incidental set_attr. Add concrete refusal/prompt/precondition and non-action acknowledgment negative examples before claiming the widened acceptance rule adequate. If no reliable general success classifier exists, document bounded acceptance limitations rather than describing it as proven semantic success.

## R1-2: typed versus manual and generated submissions are underspecified

TurnRecorder.onAcceptedSubmit is shared by keypress and Input.Inject; source is carried into the turn. Existing manual candidate branch sends observations exclusively to revision witnesses, not original calibration. A source called inject may still reflect explicit user selection, whereas stat-probe and navigation automation may be system generated. A user selecting a provisional suggestion must not itself manufacture evidence, though the later real parser response can count under an agreed rule.

Revise A1 with a source eligibility table based on actual callers: physical typing/voice, explicit object/Yourself selection, user manual override, synthetic/probe/navigation and unknown source. Preserve manual candidate precedence/revision binding and prevent one submission from contributing to both original calibration and manual witness counts. Bind pageEpoch/submissionId and static module identity before observing; reject callbacks after identity or generation changes. Clarify whether existing user-issued clicks and voice count equivalently to typing. Avoid claiming a typed-only repair when actual implementation admits all accepted submission sources.

## R1-3: a shared provider/filter order must be named

A3 says retain authority but does not specify the seam. Current ActionSynth applies authoredCommandAllowed at its final result filter; SemanticActions wraps these outputs and copies scope descriptors; Yourself separately appends exactFormsFor after normal commands. Appending generic exact forms after either path can bypass authored owner filters, nested/worn restrictions, inspect policy, stateful light scope or shared-name restrictions. Merely checking current noun/module/generation will not preserve those policies.

Revise to identify a single exact-form descriptor producer plus the common applicability/filter stage for both surfaces. List the scope descriptor fields that survive SemanticActions and precedence/deduplication, and define tap-time revalidation. A duplicate exact form must acquire any stronger authoritative scope rather than replacing or bypassing it. Explain how past success in inventory applies on ground, nested, worn and after restart: current exact record lacks context. If object-wide reusable spellings are chosen, require existing current context restrictions; otherwise persist observation context separately. Keep ordinary arbitrary exact forms distinct from canonical allowedVerbs so they do not invent semantic aliases or global capability flags.

## R1-4: identity repair requires a data-preservation decision, not only a warning

SliceB correctly refuses copying mixed records or deleting data. It must resolve this before implementation. Five release/serial stores demonstrably collide; semantic checksum identity is stronger but not collision-proof; stats unknown key and filename-owned custom slices need explicit policies. Existing owner index does not establish which individual row belongs to which of multiple owners; even a single registered owner is not proof that older unindexed data was uncontaminated.

Revise with a per-store new key/version/cache design, behavior while digest authority is unavailable, immutable observation identity, and treatment of old values. Preserve ambiguous legacy bytes as retained non-active evidence accessible to review/erase; do not silently activate them for an owner, overwrite them, or assert they are safely migratable solely from index metadata. The operator retention requirement and no-migration rule need an explicit, reviewable exception/preservation policy. Explain uninstall/reinstall and same executable under different wrapper/path, plus user-authored custom slices semantics. Audit owner generators, compaction, tombstone/revision identity and erased-reset callbacks together. General ZRamReader.gameIdentityKey changes risk non-learning consumers and are not automatically authorized by this scope.

## R1-5: separate durability lifecycle design or keep it research-only

SliceC is a source risk, excluded from observed LIGHT/DOUSE cause by parent evidence (queue0/no error). Its acknowledged flush design is not specified. A bounded timeout must not silently declare queue durable; quota drops and erase-invalidated snapshots are terminal outcomes distinct from successful write. Waiting only current queue length or _drain promise is insufficient when already draining, a later snapshot appears, or turn recording has not closed yet.

Revise C either to a separately reviewed investigation or define a captured-watermark acknowledgement covering active turn closure and all resulting snapshot IDs, failure/timeout UI and explicit exit choice, bounded waiting, cross-tab lock failure and quota terminal outcomes. Do not change native Activity exit behavior merely because browser queue risk exists; actual native lifecycle needs its own evidence. Preserve authorized exit and avoid unbounded hangs. No need to invent or reproduce a race to classify it as an unresolved design risk.
