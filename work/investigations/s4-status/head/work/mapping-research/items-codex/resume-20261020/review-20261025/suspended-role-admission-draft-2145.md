## R2 constraints after actual non-author adversarial review

The initial draft is REVISE, not implementation GO. This addendum supersedes any implication that current-value emptiness or an Inject-only check suffices.

- Guard at the role-specific dispatcher before Actionable.Submit and its Input.Clear, and before Inject early MapTopology side effects. Preserve existing manual/ordinary behavior outside the new role consumer.
- Require the exact sole matching DOM line field (including rejection of extra hidden/stale matches), bound to admitted window/request. Current generic selector cannot silently pick another field.
- Define a role-token edit revision that invalidates on user or programmatic edits, type-delete and IME composition; an empty value alone does not establish unchanged composition. If reliable edit provenance is unavailable, return unknown.
- Carry an opaque role admission token plus exact command and target through the complete chosen-command path. Do not flatten to a string and later reconstruct authority from current globals.
- Validate and dispatch synchronously, consume token on the first attempted dispatch, recheck command/target/role/enclosure/request/parser state. Any observer/listener callback that may execute between validation and actual dispatch is part of this boundary and requires revalidation or an agreed narrow dispatch seam; no unsafe atomicity claim from single-threaded JavaScript alone.
- The existing TurnRecorder stamp records wrapper submission intent before key delivery, not VM receipt. Keep request identity and actual VM wait/context as separate proof. Do not rename wrapper history into accepted parser receipt.

These remain design requirements. Exact API, edit mechanism, callback-safe dispatch and exhaustive ordinary-context qualification remain open; no code or facts may be inferred approved.
