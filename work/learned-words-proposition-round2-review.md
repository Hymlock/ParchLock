Accepted resolutions: provider/semantic versus learned distinction with no universal verb list; manual and inspect rows retained; session-only first-try display with unchanged writer and per-object threshold; exactly one initial Status pane including honest empty state; cumulative ordered headers; existing toolbar accessible strings with collapsed icons and tour restoration; display-only observed spelling and existing instance labels; ambiguous story-mark kind correction with unchanged command-string intersection, directEvidenceOnly, null objectId and ambiguous-reference learning exclusion. Room context removes drop/remove/wear (ActionSynth:239-242), so the retained intersection is a substantive safeguard; Take remains evidence-dependent. No changes to inventory callers or ActionSynth inventory removal are proposed.

R1. Module-load boundary is not a reset of persisted learning. #1074 says confirmed entries stay until module reset and defines reset as existing gameIdentityKey/module-load boundary. AttrCalibrator.hydrate(:905-921) explicitly reads PL_AttrCalib_<key> again, and persist(:923-928) retains it. Reloading/reopening the same module therefore restores confirmed and one-confirmation counts; changing key selects a different store, it does not delete the previous module's evidence. PRODUCTION_PLAN D205 Learning(:7625-7632) requires cross-reload persistence and existing hydrate/forget contracts. Amendment: same-module reload/navigation/story switch clears transient display but preserves identity-scoped evidence/confirmed membership; switching module isolates the visible store and returning restores it. Restore/undo clear transient display only. An actual existing explicit forget/reset operation, if one exists and is intended, must be named by code path and narrowly scoped; do not invent an automatic purge or equate module load with evidence reset. If no explicit reset path is in scope, avoid promising one. Add reload-away-return versus explicitly authorized forget tests.

R2. LoadSeq does not assign absent ordinals. EquipmentUI.loadSeq(:132-149) only reads an existing sequence. EquipmentUI.model(:256-260) assigns and persists ordinals for current inventory; room/discovered objects are not registered there. LearnedWords.records(:125/:157-165) also includes scoped room objects. Editor-first launch on a fresh store and an object never carried will therefore have _seq[id] undefined if the implementation just calls loadSeq. Amendment: reuse the single existing EquipmentUI allocation/persistence owner for any real current-scope row requiring differentiation; register missing ids once through that owner, retaining _seq/_seqNext/seqKey and existing instance N text, never a second sequence. Explicitly cover editor-before-equipment, duplicate ground objects, subsequent equipment rendering and cross-reload stability. No demo/projection-only fake ids should enter the persistent sequence. If extending the existing registration owner is rejected, require an honest unallocated fallback and stop promising every row can distinguish copies. Prefer the first option.

R3. Freeze known-versus-learned provenance independently of learned projection, and define legacy migration. ActionSynth.verbsForAttrs(:74-77) includes AttrCalibrator.allowedVerbsFor; commandsForObject(:257) appends LearnedWords.commands. Calling the pre-observation lane without excluding these learned contributions can classify an existing newly learned command as provider-known. Current exactForms/allowedVerbs rows have no pre-learning-known marker (LearnedWords.records:125-140). Existing users' historical rows cannot be reconstructed as pre-learning snapshots from today's radial. Amendment: classify new observations using independently provided/semantic commands with learned/manual contributions suppressed for that calculation, without changing normal synthesis or stored evidence. Persist the minimal fixed membership provenance through an existing owned record/override mechanism, specifying ownership without changing confirmation semantics. Legacy rows with missing provenance stay visible conservatively; do not retroactively remove them by using contaminated current output or a hardcoded list. A later independent provider capability may appear in Story actions but must not erase an established learned row solely because it became provider-backed. Provisional session metadata must not become command eligibility. Required tests include legacy records, independently provided capability versus prior learned-only capability, manual replacements, and reload of fixed membership.

Additional retained guardrails: shared observed spelling does not prove physical identity; keep dictionary-encoder contiguous matching, no cross-punctuation or unseen expansion, no command/referenceFor change. Instance ordinals never bind parser targets or enter command/autocomplete/story speech. Initial Status must explain available model facts only, including missing/hidden values as unknown where applicable; do not fabricate conditions. Toolbar icons use existing accessible names and leave a usable way to access each action; the tutorial restores prior presentation.

Please incorporate R1-R3 and return a single reconciled proposition for final design agreement. No additional feature request and no runtime implementation in this round.
