## Exit flush accepted, one navigation-abort defect

LearningStores.flush joins actual activeDrain under existing lock, then checks queue/draining/quota/lock/recovery state; timeout reports failure. TurnRecorder.whenSettled tracks all unresolved timers including boundary-stamped turns; settlement completes after analyzers. Workspace waits settlement then flush, freezes Input.Inject and physical VM dispatch, retains page on failure, and offers retry. Explicit library/restart callers use the barrier. Force-close, OS kill and unrelated navigation are outside this bounded guarantee.

**Remaining P2:** WorkspaceUI.LeaveWithLearning runs `if(ok) { navigate(); return; }`, retaining _leaving=true and its document blocker permanently whenever navigate returns without starting navigation. The story-ended restart callback explicitly returns early if SaveState.prepareNewGame() is false; PlaythroughState.prepare can return false for absent context or failed intent write (SaveState:355-361). The callback also catches navigation exceptions internally and returns normally. In either path the page remains open but frozen and no exit retry state is shown. This is a real pre-existing failure outcome newly wrapped by persistent freeze, not a hypothetical unsupported browser scenario.

Finite correction: callback reports whether navigation was initiated (false on early-return/caught failure), and LeaveWithLearning releases _leaving/blocker when it was not; alternatively reset via a shared finally/abort hook. Do not leave restart intent prepared on caught navigation failure. Existing library callback must report initiation consistently. A throw can already reach outer cleanup; either return false or propagate is sufficient if all paths honor the contract. Root was notified before this report.
