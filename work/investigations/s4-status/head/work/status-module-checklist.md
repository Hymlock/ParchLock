## Replication runbook

1. Purpose. Boot each GameList module in checklist order. Record what the current StatTracker would confirm, plus numbers the story prints that it does not confirm. Do not change the player app.

2. Where the files are. Checklist: `work/status-module-checklist.md`. Runner: `work/status-audit/zbatch.mjs`. It decodes `games/<file>` with `harness/decode-story-js.js`, spawns `work/status-audit/zvmram.mjs` (Bocfel), and writes `work/status-audit/z/` (`results.json`, `<story>.txt`, `<story>.snaps.json`). Catalog: `js/GameList.js`. 309 launchable modules. Glulx are the `.gblorb.js` stories. Do not claim Z-machine RAM for Glulx. `zvmram.mjs` searches a Z-machine image (header serial, globals) and does not apply to those files.

3. Order. Do not skip ahead. Boxes already marked stay marked. Still open when this was written: `chico.z5.js` (menu never became a line prompt) and possibly Silence of the Lambs 2 (`lambs2.z5.js`) if the last reopen did not finish. Next never-started file last reported was `lists.z5.js`. Verify against the checklist rather than trusting this sentence if the file has moved on. The first 11 Glulx already had a help pass.

4. Commands, in order, only after a real line prompt:
   1. Answer a continue (y/n) with yes. Answer a restore question with no. If no would end the story, answer yes.
   2. An opening question is not the command prompt. Do not type score into it.
   3. Then: score, diagnose, help, inventory, inventory again.
   4. If inventory is not a game word, send i twice instead.
   5. A figure is repeating only when both inventory replies print it. One reply only is a one-off, not standing status. Wumpus (`wump2ka.z5.js`) was the check: both replies printed "You are carrying 4 lbs of stuff (10% of your current capacity). It's all worth about $35." Value 35, weight 4, and capacity 10% repeat. SCORE did not print them. Help only described them.
   The runner still does the old thing. From the repo root: `node work/status-audit/zbatch.mjs`, `node work/status-audit/zbatch.mjs <limit> <start>`, or `node work/status-audit/zbatch.mjs <file.js>[,file.js]`. Flags: `--help-only`, `--inventory-only`. The default queue is still score, diagnose, inventory, inventory, help. `--inventory-only` is inventory, inventory. `--help-only` is help, then it keeps the old score and diagnose replies. A yes/no line, including continue, is still answered no (up to two gates). That is how `lambs2.z5.js` ended. Restore ("would you like to restore") is answered no. It does not switch to yes when no would end the story. Any other line prompt, including an opening question, still gets the next queued command, so score can land in that question. It still sends inventory first, and sends i twice only after a reply that says not a verb, don't recognise/recognize, not understood, or unknown word. `StatTracker.observeCarryText` still confirms value, weight, and capacity on the first matching inventory line. Do not treat that one reply as repeating. The built-in `games` list is still only `inhumane.z5.js` through `limp.z5.js`. A filename only filters that list, so `lists.z5.js` is not booted. A normal run SKIPs a file whose saved help reply is longer than 20 characters.

5. Help commands. Save the full help text. Send a command when help or the score reply tells the player to type that word (SUMMARY, FULL SCORE, STATUS, and any unfamiliar word named that way). Do not send glue or example junk: not "or" from "ENTER or CLIMB", not "it" from "type it", not "simple" from "type in simple english phrases", not "effort" from "saves typing effort", not "Type mismatch!". Still skip ordinary movement and meta verbs (look, examine, take, north, save, restore, quit, hints). Inventory is no longer on that skip list. No cap of four extras.
   `replies.help` and the `.txt` transcript keep the full help text. Other replies in `results.json` are cut at 900 characters. `extraStatusCommands` does not stop at four, and its blocked set does not include inventory. It already skips unquoted "it"/"on", the word "mismatch", and any phrase that contains "or". It still captures "simple" and "effort" (on `karn.z5.js` both were prose, not verbs). It also takes "commands such as" lists, and when the text says words are meant to be typed as commands it still considers scoring, status, summary, health, vitals, and full score. Extras are queued only after the initial queue is empty and a line prompt is back. Follow the list in this step when that differs.

6. Pagers. On [Please press SPACE.], [More], or press any key, send space immediately. Help menus: at most two pages, then a quit letter only if that letter was printed on a captured page. 7. How to judge a reply.
   - Tracked: current StatTracker would confirm it, or a number repeated on both inventory replies.
   - A printed zero at the start counts as the stat existing when the wording is a status reply.
   - Not ready: the reply says there is not enough information yet, barely started, or unstarted. The command exists. Do not mark the stat missing.
   - No score: copy the exact sentence. The tracker only treats "there is no scoring in this game" and "this game has no / does not have a score" as no-score. "There is no score in this story." is not that phrase. Record it anyway.
   - Printed but not confirmed: a maximum, rank, locations, treasures, or other number the reply printed that StatTracker did not store. Quote the sentence.
   - RAM: on Z-machine only, note when a global equals the printed number. Equality is not a pin. A pin is only when StatTracker confirmed the slot because the value changed the way it requires.
   A parsed SCORE or DIAGNOSE reply confirms on that reply, including a parsed 0. `NO_SCORE` in `js/StatTracker.js` is `there is no scoring in this game` or `this game has no / does not have a score`. A status grid still needs two sightings (`CONFIRM_SAMPLES` is 2). `analyze` calls `observe` twice on the same snapshot, so one grid sighting can look confirmed in `results.json`. Do not count that double call as two sightings. StatTracker has no not-ready flag. Record it, and do not mark scoring unavailable from the wider test. `LDoDoom.z5.js` prints "There is no scoring in this game.", which is the tracker phrase.
