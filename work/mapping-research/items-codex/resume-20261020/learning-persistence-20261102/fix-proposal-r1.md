## Slice B: module identity isolation

Five stores currently key values by release+serial. Independent static decoding proves HugeCave and eric_dm both1-000001 despite different executables/checksums. Ownership index protects erase, but does not partition shared payloads/caches. Bind learned knowledge to exact immutable executable identity through the established ModuleLibrary authority; handle unavailable identity explicitly before observing/hydrating, with no shared 'unknown' namespace. Audit all seven store key builders/caches rather than patching AttrCalib alone.

Do not discard existing data or silently copy mixed legacy rows to a guessed module. Existing ownership/provenance, multi-owner/overflow cases, user-created words and uninstall/reinstall retention require an explicit data-preservation design. The no-migrations development rule and operator's stronger learning-retention requirement must be reconciled by actual design review; no implicit destructive reset is authorized. This is a separate confirmed isolation defect, not claimed as the cause of a same-module-only quit.

## Slice C: acknowledged durability / exit lifecycle

LearningStores same-page reads can return queued values. Inspect actual quit flow and outstanding writes; do not show a queue-only fact as durably stored. Any durability barrier must respect Web Locks, erase epochs/tombstones, FIFO immutable snapshots, quota compaction/error reporting and current module identity. Existing _drain returns early while already draining and is not by itself an acknowledged flush API. Do not bypass its serialization or hang exit indefinitely. This risk is source-level; ordinary settled-write tests do not establish it caused the operator's event.
