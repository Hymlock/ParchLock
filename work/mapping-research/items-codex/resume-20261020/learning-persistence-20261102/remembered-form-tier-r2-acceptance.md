# Remembered item/form product tier — finite R2 acceptance

2026-11-02. Read-only design review of root's concrete interpretation against the operator's learning-over-radial-usage requirement. No code/tests/native. Verdict: ACCEPT WITH THE FINITE CONDITIONS BELOW; no requirement for a universal semantic-success classifier.

The proposed tier is coherent and useful: remember the exact object/form pair the player explicitly tried, preserve it independently of game saves/quits, and prefer that remembered pair over usage ranking after two distinct qualifying observations. This is preference learning about an attempted spelling, not proof of capability or successful effect. The existing complete-form click policy already allows a parser attempt, so remembered priority can improve discovery without admitting new semantic flags or bypassing current scope. The amendment is sufficiently concrete to implement after these conditions are adopted.

## Required finite conditions

1. **Explicit producer allowlist.** Typed/user-send/user-voice/user-selected full radial or history form may contribute; system/navigation/probes/ambiguous/unknown cannot. Current `inject` alone is insufficient because it combines these producers. Carry immutable producer metadata into the accepted event at existing submission seams. A stem/menu open/voice insertion without actual Enter contributes nothing. A full suggestion clicked once can contribute only its later bounded response, never the click itself.
2. **Exact pair, lexical/reference eligibility.** Store module executable identity + objectId + exact verb form, with unique verified noun correlation at dispatch. Generic support is one leading dictionary verb plus verified object noun; only already recognized multiword aliases are allowed. No global verb/capability flag, no arbitrary instrument/topic/compound parsing. Noun display spelling can change; re-resolve the current verified noun for that object at use. Do not equate equal words on different objects.
3. **Honest witness threshold.** Two distinct submission witnesses with attributable nonempty bounded game response and no existing refusal/prompt/precondition signals qualify *remembered preference* only. Name this `remembered` / `response-observed`, never semantic `success`, `opcode-state`, `allowedVerb` or `confirmedCapability`. Reuse refusal heuristics conservatively, document their incompleteness, and do not require universal success inference. Repeated generic acknowledgments may qualify preference under this explicitly weak policy; that is acceptable because the tier claims only repeated player attempts with non-refusal output. This revises the earlier attempt-only design's prohibition on priority qualification.
4. **Bounded outcome exclusions.** Preserve frozen recorder slice and boundary capture, not live DOM at delayed analyze. Exclude hidden probe echoes, input echo-only output, empty output, explicit refusal, known disambiguation/incomplete/yes-no/continuation prompts and precondition messages. A 450ms closure or next dispatch alone is not a positive witness; bounded output is also required. Unknown game-specific failure can escape the heuristic; acknowledge that limitation without blocking this preference feature. Do not add an engine-wide prompt-completion project to this patch.
5. **Identity/lifetime binding.** Freeze authoritative module identity, pageEpoch/submissionId and resync generation at dispatch; recheck before applying outcome. Reject stale callbacks after switch/restore/restart or candidate revision change. Deduplicate witnesses across callbacks/closures; source metadata cannot be inferred from later global state. Missing module identity must not write new weak-key durable records. Same exact executable at a new path retains knowledge under root's reviewed identity scheme.
6. **Manual branch exclusivity.** Existing edited/manual candidate wins and routes to its revision-bound witness mechanism only. Do not award original form plus replacement evidence from one submission. Existing manual authoring persists independently; do not overwrite original opcode/calibration facts.
7. **Priority and current authority.** Only a qualified remembered exact pair or existing stronger confirmed exact pair gets learned priority. Ordinary dictionary suggestions, raw attempts <2, edited labels, raw usage and diagnostic confidence do not. Add a separate learned-priority field to the actual rendered descriptors consumed by the shared ranker; among ordinary entries retain D110 usage/prior/order. Preserve existing full-form click behavior and current object/context filters. Existing authoritative semantic forms and scope descriptors remain stronger; duplicate remembered form merges learned provenance into the authoritative descriptor rather than replacing it. Strong negative/state/context guards cannot be bypassed by past observations.
8. **Durability and failure.** Save attempts/qualification under the new module store policy at learning time, independent of save snapshots. Persist counts plus enough witness deduplication/provenance to avoid re-counting one event; apply reviewed bounds/quota ownership behavior. Do not claim successful durability on failed storage, nor let teardown clear current knowledge before pending outcomes are handled by the agreed lifecycle contract. No native lifecycle expansion is required by this acceptance.

## User-visible acceptance cases

- Explicitly type LIGHT lamp twice; each produces game output without recognized refusal/prompt. It becomes a remembered lamp/LIGHT preference, survives quit/reopen without game save, and outranks a more-used unlearned action for that item. It does not mark lamp switchable/light-source or infer ON state.
- DOUSE lamp similarly qualifies its own exact pair; the LIGHT pair does not manufacture DOUSE, and the same verb on another object remains unqualified.
- A prior confirmed semantic form with live owner/state scope keeps those checks and receives learned provenance/priority without admitting an opposite-state or unavailable action.
- A system probe, queued route, unknown inject caller, failed blocked submission, editable stem, one observation, explicit refusal or known clarification prompt does not qualify.
- All-unlearned menu order remains D110. Tools/history authored ordering remains unchanged unless the reviewed product explicitly routes an object action menu through the common ranker.
- Restore/restart changes the live world but retains module preference; missing object/current invalid noun/current context veto prevents execution despite retained knowledge.

These are finite implementation acceptance conditions, not a request for universal proof. Root may implement this separate remembered preference tier without broadening existing semantic calibration. Subsequent audit should reject only concrete violations of these conditions or actual current-source authority conflicts, not demand a general natural-language success classifier.
