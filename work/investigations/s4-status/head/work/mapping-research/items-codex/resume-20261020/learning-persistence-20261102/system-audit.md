## Erase and durability controls

LearningStores.read (224) returns newest queued snapshot before storage, records hydration revision/erase epoch. Persist takes immutable snapshots; Web Lock FIFO commits metadata/readback before value. Invalid/missing index fails conservative erase; lock unavailable disables erase but normal writes fall back synchronously. Registered per-kind compaction retries quota once, then reports storage full/drops that snapshot; no arbitrary cross-store eviction. Async failures retain queue/retry warning. There is no acknowledged durability barrier in quit path from bounded search; queued visibility must not be presented as confirmed disk durability. Parent's queue0 + no error excludes this as observed LIGHT/DOUSE cause.

Erase listing (LearningStores390-435) protects any live installed path/current path or any recorded digest matching installed/current digest. Unknown installed digests, missing digest owners, lost path-only owners, legacy owner overflow fail closed. Digest set is durable while recent owner list bounded16. Erase revalidates listing signature/current value inside lock, writes tombstones/pending before removal, checks readback and revision, rejects stale queued writes via epoch/reset. Uninstall removes neither learning stores nor their owner history. These controls protect deletion; multiple owner digests attached to one header key still read/write one shared VALUE.

Other binary/wrapper encodings were not counted; this is existence proof, not full collision census.

## Evaluation of generic fix direction (not an agreed proposal)

Broadening observer eligibility from RPG whitelist to dictionary-valid one-object exact forms with a unique verified current scoped noun addresses the demonstrated omission without LIGHT/DOUSE exceptions. Keep manual-revision evidence separate. Existing generic split handles leading single word plus noun and recognized multiword synonyms; it does not prove arbitrary multiword grammar/arity. Do not overclaim support for all commands.

Keep exact spelling evidence separate from canonical allowedVerbs and from attribute-bit inference. Broad extra verbs have no successOps mapping; a set_attr seen during unknown command is not by itself proof of its intended action. Two bounded non-refusal behavioral observations can meet existing exact-form policy, but generic negative matching is fallible (narrative questions, indirect failure/precondition prose). Preserve frozen response, rejected/ambiguous gates, deduplicated page/submission witnesses, dictionary and object correlation; add adversarial controls before widening. Do not train merely because a lexical suggestion exists or command was submitted.

Project remembered exact forms into ordinary object AND Yourself consumers through one owner function, using current scoped verified noun and existing held/nested/worn/owner restrictions. Do not add arbitrary strings to ActionSynth.rules, invent canonical semantics, or let learning bypass lightFormScope/identityWear/worn-removal, authored capability restrictions, shared-name ambiguity or tap-time revalidation. A learned past success permits a command spelling; it cannot freeze previous lamp state, held context, door lock, score or inventory location. Context policy should be explicit: current exact records lack persisted context, so either demonstrate object-wide reusable command policy or extend evidence schema to preserve applicable context without erasing learned knowledge on restore.

Unify durable learning identity on static executable identity (prefer existing ModuleLibrary authenticated executable digest) with fail-closed readiness before hydrate/write. Avoid mutable VM-memory hash and broad change to ZRamReader.gameIdentityKey without auditing all non-learning consumers. Decide custom-slice path preference policy separately. Existing developmental no-migration rule means old colliding evidence must not be silently trusted/moved to a digest; explicit fresh-key strategy and erase/index behavior belong proposal. Record static identity at observation and recheck commit to prevent late callbacks writing another module's facts.

Required review controls: confirmed exact form normal reload/noSAVE, earlier save restore, restart, same object on ground/held/nested/worn; two distinct binaries with same header; different wrapper same executable; key not-ready; stale callback/module switch; dictionary miss, ambiguous/unverified noun, refusal/question/precondition, duplicate submission, manual revision/ignore; ordinary and Yourself parity; all seven owner persistence/erase/queue/quota semantics. This bounded audit establishes source contracts and two isolation examples, not implementation acceptance or full learned-system certification.
