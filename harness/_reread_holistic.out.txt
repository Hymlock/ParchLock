########## PLAN Objective @ 1592 ##########
Objective (consolidated)

Build a **turn-synchronous overlay** whose UI is driven by a **normalized world-model payload**, not by ad-hoc DOM scraping:

1. Maintain a **WorldModel Translator** that always emits one `UIPayload` (with confidence / provenance).
2. Feed that translator from **pluggable providers** (behavioral Glk/commands, Z RAM, Inform-Glulx RAM, heuristic text) - never a single fragile source.
3. Apply a **Text-Gated Visibility Shield** so undiscovered entities are not spoiled by default.
4. Synthesize **state-aware actions** for radials when structural data exists; keep safe generics in heuristic mode.
5. Drive map, inventory tree, HUD, and pathfinding from the payload.
6. **Degrade gracefully** when RAM introspection is unavailable.
7. **Deterministic structural primary (D17):** when P2/P3 RAM data is available, map identity and actionable words MUST come from VM object IDs / dictionary bindings / in-scope children ? not from fragile prose text-mining. P1 heuristic is forever-fallback only.
8. **Universal coverage (D22):** the same P2/P3 deterministic path MUST work for **every room/location**, **every catalog story module**, and **every supported module system** (Z3/Z5/Z8/Zblorb on Quixe; Glulx when under the same chrome; specialized modules like wump2ka/yagwad via the same play.html Translator). Alley/Anchorhead is a **fixture only**, never a product dependency or code branch. The RAM miner must be holistic for all rooms/modules/systems.


**Non-goals**
- General IF IDE/debugger UI.
- Perfect spoiler-free play for every experimental Inform extension.
- Shipping SKSE/Skyrim into Parchmap (DevKits = toolchain patterns only).
- Covering author Glk graphics with our canvas.
- Blocking all UI progress until RAM mining is "complete."

1. Node Clustering & Constrained Physics:

   - Non-Cardinal Edges: Apply soft distance springs between nodes or clusters.

   - Anchor non-cardinal edge lines directly to the perimeter of the respective cluster nodes.
The map layout engine actively runs a continuous Graph Beautification Pipeline to ensure the canvas remains clean, readable, and intuitive to navigate at a glance.

Instead of letting nodes scatter into a chaotic spiderweb, the layout engine enforces five core aesthetic and readability rules:

Core Layout Beautification Rules
Edge-Crossing Minimization (Planarization): The solver continuously calculates edge routes to prevent connector lines from crossing over each other or passing straight through room boxes.

Orthogonal Grid Alignment: Cardinal exits (N/S/E/W) snap strictly to $90^\circ$ right angles and clean grid lines. Parallel hallways render as straight rows rather than jagged stair-steps.

Label & Node Collision Prevention: Room title boxes, exit badges, and item indicators dynamically repel neighboring elements, ensuring text never overlaps or becomes obscured.

Hierarchical Elevation Layering (Vertical Stacking): Exits like UP, DOWN, CLIMB, or ENTER CELLAR automatically assign nodes to distinct elevation planes or tabbed floor layers, preventing multi-story buildings from collapsing into a single flat mess.

Sub-Map Clustering: Rooms inside a distinct structure (e.g., a mansion interior vs. the surrounding forest) compact into distinct visual regions, drawing clean boundary hulls around separate zones.
