# Sherlock Z-text escape: compared proposal, before implementation

Codex source audit and independent problem-only investigation by `/root/sorcerer_worn_blind` agree that `_decodeZscRaw` recognizes A2/6 but fails to consume the two following payload units. Actual original Sherlock dictionary vectors decode ASCII36 as an abbreviation instead. Neither investigation establishes Sherlock grammar metadata or classification. Existing D143 abbreviation-space repair must remain intact.

Proposed bounded repair in the existing decoder: track an escape's two payload units across packed words, consume them before interpreting control characters, emit printable ASCII32..126 and newline13, ignore null0 and unsupported codes, then resume alphabet0. Ignore incomplete escape at termination/maxWords. Preserve recursive raw abbreviation spaces and normalize once in public decodeZsc. Do not change classifier entry-size limits, family activation, dictionary metadata layout, V1/V2 shift behavior or custom alphabet support.

Character-conversion audit: bundled lib/zvm.js owns a VM-specific unicode_table containing ASCII, newline and default/header-specific extended mappings. ZRamReader receives raw memory and has no qualified VM-instance table contract. This proposal therefore does not call that internal table or equate high ZSCII codes with Unicode. Unsupported extended payloads are consumed without fabricated text. Full Unicode/custom-alphabet decoding remains an explicit separate scope.

Required regression controls: actual Sherlock first three dictionary entries, cross-word escape payloads including control-shaped payloads, return to A0, multiple escapes, null/newline/ASCII bounds, unsupported high values, truncated final word/maxWords, existing D143 abbreviation spaces and original non-escape names. Demonstrate baseline failure, independent design consensus before shared edit, non-author current-source review, operator gate and one fresh immutable full catalog comparison across three engines after the preceding Spellbreaker candidate is accepted. This proposal authorizes no concurrent change to the frozen candidate.

Specification corroboration: https://inform-fiction.ifarchive.org/zmachine/standards/z1point1/sect03.html sections3.4,3.6.1,3.8. Supported ASCII is sufficient for the measured dollar-sign vectors; no whole-title or whole-decoder completion inferred.

Independent adversarial design review by `/root/zil_food_independent`: ACCEPT before implementation, requiring payload-first ordering, A0 reset even unsupported/null, truncation without reading an extra word, actual original-memory vectors and D143 guards. This is subagent provenance, not an authenticated old-seat acceptance.
